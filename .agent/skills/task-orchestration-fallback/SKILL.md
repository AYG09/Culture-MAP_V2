# Shrimp 대체 태스크 오케스트레이션

Shrimp Task Manager MCP를 사용할 수 없거나 불안정할 때, 동일 목적(계획·분해·실행·검증)을 **문서 기반**으로 대체하는 절차입니다.

---

## 핵심 원칙

1. **증거 기반 계획**: 코드/문서/로그를 확인한 사실만 반영한다.
2. **최소 변경**: 기존 아키텍처와 패턴을 유지한다.
3. **검증 우선**: 완료 기준을 먼저 정의하고, 실행 후 확인한다.

---

## ✅ 대체 워크플로우

### 1) 요구사항 정리
- [ ] 목표/범위/제약을 한 줄 요약한다.
- [ ] 관련 파일(TO_MODIFY/REFERENCE/CREATE)을 목록화한다.

### 2) 설계 스케치
- [ ] 데이터 흐름(입력→처리→출력)을 간단히 서술한다.
- [ ] 필요한 인터페이스(함수/이벤트/타입)를 명시한다.

### 3) 태스크 분해 (3~7개)
- [ ] 각 태스크는 1~2일 내 완료 가능한 크기
- [ ] 의존성을 명확히 표기
- [ ] 검증 기준(수동/자동)을 태스크마다 포함

### 4) 실행 체크리스트
- [ ] 변경 범위 최소화
- [ ] 기존 패턴/네이밍 준수
- [ ] 컴파일/에러 확인

### 5) 검증
- [ ] 수동 시나리오 확인
- [ ] 필요 시 콘솔/로그 캡처

## 적용 기준

- Shrimp MCP 도구 호출 실패/비활성화/정책상 사용 불가 시 사용
- 태스크 관리가 필요한 모든 변경(기능 추가/리팩터링/버그 수정)에 적용
